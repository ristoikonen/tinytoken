Command-line reference

TinyToken provides a command-line interface for creating, inspecting and verifying compact, cryptographically attested image and document tokens.

tinytoken

Create a TinyToken from an image or document, or inspect an existing .token file.

Syntax
tinytoken <file> [options]

Arguments

<file>
Source file path (image, document, or existing .token file). REQUIRED

Options

-o, --out <path>
Custom output .token path. Defaults to <input_dir>/<basename>.token.
-v, --verify
Explicitly run and print decode and cryptographic signature audit.
--info
Verbose breakdown: token size, uncompressed estimate, dates and all fields.
--filetype
Print preview filetype (e.g. WEBP, PNG, JPEG, AVIF).
--preview
Stream raw binary preview data to stdout (for saving or piping).
--json
Print token metadata, attestation and Merkle proof as JSON to stdout.
-h, --help
Display this help message.

Examples

Inspect an existing token using the available inspection options.

Inspect token information 
# Inspect an existing token
tinytoken tok_00004_Henri.jpg.token --info
Detect preview filetype 
tinytoken tok_00004_Henri.jpg.token --filetype
Extract preview 
tinytoken tok_00004_Henri.jpg.token --preview > preview.webp
Verify token integrity 
tinytoken tok_00004_Henri.jpg.token -v

Create a token

Create tokens from images or documents. Specify a custom output location when required.

Tokenize an image 
# Create a token from an image
bun tinytoken ./images/Henri.jpg
Tokenize a document 
# Create a token with a custom output path
bun tinytoken ./documents/report.pdf -o ./output/report.token --info

generate

Create a compact, self-attesting 25 KB TinyToken (.token) from an image or document file.

Syntax
tinytoken <source-file> [-o <output-path>] [--info]

Arguments

<source-file>
Source asset path to tokenize. Supports images (JPEG, PNG, WebP, AVIF, SVG, BMP) and documents (PDF, DOCX, TXT, MD, CSV, JSON, LOG, YAML). REQUIRED

Options

-o, --out <path>
Custom destination .token path. Defaults to <input_dir>/<basename>.token.
--info
Print verbose breakdown immediately after encoding: Section I header, QuickLZ compression ratio, VQ centroids, DINOv3 visual embedding, and BGE semantic text embedding.
ℹ
Document Multi-Page Tokenization: Multi-page PDFs generate sequential page tokens (_p1_, _p2_, _p3_) up to maxPagesPerDocument (default 3), rasterized with Chrome PDFium WASM at 150 DPI and paired with clean Unicode text layers.

Examples

Tokenize a PDF document with BGE embeddings 
# Tokenize a PDF with full metadata breakdown
bun tinytoken ./documents/annual_report.pdf -o ./output/annual_report.token --info
Tokenize a Markdown or text file 
# Tokenize a text document
bun tinytoken ./documents/notes.md --info

struct

Perform ultra-fast zero-copy binary inspection of Section I headers in sub-microsecond time (<1 µs). Inspects raw 25 KB tokens, entire archives (tokens.zip), or directories with zero QuickLZ decompression, zero JSON parsing, and zero cryptographic verification overhead.

Syntax
tinytoken struct <target> [-f <field>] [--format <table|csv|json|raw-hex>] [--limit <n>]

Arguments

<target>
A single .token file, a ZIP archive containing tokens (tokens.zip), or a directory of token files. REQUIRED

Options

-f, --field <name>
Extract a single field to stdout. Fast for shell scripts and pipelines: uuid, merkle, dims, flags, ts, sizes, vq, model, ocr, dino, bge, tags.
--format <fmt>
Output formatting mode: table (default), csv, json, or raw-hex.
--limit <n>
Maximum number of entries to inspect when scanning an archive or directory.
--decode-meta
On-demand Section II QuickLZ metadata unpack (only when requesting text or embedding fields).

Examples

Fast zero-copy field extraction 
# Extract SHA-256 Merkle root in sub-0.05ms
tinytoken tok_00001_report.pdf.token -f merkle

# Extract BGE text embedding vector
tinytoken tok_00001_report.pdf.token -f bge
Scan an entire token archive 
# Inspect first 15 tokens in archive with zero decompression overhead
tinytoken struct ./data/tokens.zip --limit 15

search

TinyToken's built-in in-memory engine (CompressedTokenSearchEngine) indexes tens of thousands of tokens into RAM in under 50 ms. Search supports 4 complementary modalities:

OCR & Substring Search
Searches token filenames and extracted Unicode text layers with instant sub-millisecond prefix/substring filtering.
VQ Visual Similarity (ADC)
Asymmetric Distance Computation over 16×16 color codebook grids in O(1) time using a precomputed 256×256 distance LUT. Evaluates 10,000 tokens in RAM in ~1.5 ms without GPU.
DINOv3 Visual Cosine
Meta ViT-S/16 384-byte Int8 embeddings ranked by cosine similarity for illumination- and angle-invariant visual scene matching.
BGE Semantic Text Search
BAAI bge-small-en-v1.5 384-byte Int8 text embeddings ranked by semantic cosine similarity for conceptual text search across documents.

Examples

Search API endpoints 
# OCR substring search
curl "http://localhost:3000/api/search?q=invoice"

# Reverse visual similarity search
curl "http://localhost:3000/api/search/similar?id=tok_00001_p1_report.pdf"

Dual Embeddings (DINOv3 + BGE)

TinyToken integrates two independent 384-dimensional Int8 neural representations within its self-attesting 25 KB envelope: a visual embedding (Meta DINOv3 ViT-S/16) and a semantic text embedding (BAAI bge-small-en-v1.5).

Output Embedding
Model
Dimension & Size
Primary Domain
Visual Embedding
Meta DINOv3 ViT-S/16 ONNX (q8)
384-dim · 384 bytes Int8
Visual layout, objects, textures, camera geometry
Semantic Text Embedding
BAAI bge-small-en-v1.5 ONNX (q8)
384-dim · 384 bytes Int8
Document semantics, text meaning, conceptual topics

How Document Text Embedding Works

When processing document files (.pdf, .docx, .txt, .md, .csv, .json, .log, .yaml), the pipeline executes:

  1. Text Extraction: Extracted via Chrome PDFium WASM (PDF), XML streaming parser (DOCX), or Bun UTF-8 streaming (plain text and markdown).
  2. Token-Aware Clipping: Text is capped according to APP_CLIP_TEXT_LIMIT_CHARS (default 2200 characters) to ensure the token envelope never exceeds 25 KB.
  3. ONNX Feature Extraction: Runs BAAI's BERT-based sentence encoder using @huggingface/transformers with q8 quantized weights cached in ./.cache/transformers.
  4. L2 Normalization & Int8 Quantization: The 384-dimensional [CLS] representation is L2-normalized and scalar-quantized to an Int8Array(384).
  5. Zero-Copy Storage: Encoded as a 768-character hex string in Section II metadata and indexed in the ZIP central manifest (_index.json) for instant RAM retrieval without unpacking.
💡
Dual-Score Fused Metric: In search operations, visual geometry and semantic text fidelity can be evaluated together:
Fused Score = α · Text_Cosine + (1 - α) · Visual_Overlap
This prevents false positive matches where scenes share similar color distributions but completely different semantic contexts.
