TinyToken Commands

TinyToken provides a modular command suite for packing, inspecting, indexing, searching, and streaming compact 25 KB self-attesting image and document tokens. Select a command card below to jump directly to its specification and syntax.

tinytoken

Core CLI foundation, environment requirements, and binary format invariants

GF(2^8) V2 Engine

TinyToken is an ultra-dense, self-attesting 25 KB binary token format combining $GF(2^8)$ Galois Field arithmetic, a 256-color perceptual VQ-VAE lattice, Meta DINOv3 ViT-S/16 semantic embeddings, and Ed25519 detached signatures. All commands conform to strict performance and memory constraints.

System Requirements: Bun runtime (>= 1.1.0), native typed arrays, and a maximum token envelope ceiling of strictly 25,600 bytes (25 KB).

Binary Envelope Architecture

Section Offset Range Max Size Contents & Cryptographic Bounds
Section I: Origin Header 0 .. 703 704 B (Fixed) Magic "GF28", UUID, 256B Ed25519 signature + Merkle root, 256B VQ 16x16 grid, 64B $GF(2^8)$ Reed-Solomon parity.
Section II: Metadata & OCR 704 .. 704 + metaLen ≤ 4,096 B QuickLZ compressed JSON payload containing asset metadata, OCR text witness, and 384-byte DINOv3 ViT-S/16 Int8 vector.
Section III: Raster Preview metaEnd .. End ≤ 20,800 B High-efficiency 320x320 WebP/AVIF visual preview thumbnail.
tinytoken [command] [arguments...] [options]

tokenize

Single-token inspector, verifier, and standalone tokenizer

cli.ts / bun tokenize

Inspects an existing .token file, audits its Ed25519 signature and Merkle root, extracts the high-resolution raster preview, or tokenizes a single image/document asset.

tinytoken <file> [options]

Arguments & Options

Parameter Type Description
<file> REQUIRED Path Source asset path (image/doc) to tokenize, or path to an existing .token file.
-o, --out <path> Path Custom output destination. Defaults to <input_dir>/<basename>.token.
--info Flag Verbose breakdown: token size, uncompressed estimate, dates, all fields across Sections I, II, and III.
--filetype Flag Outputs clean preview format name (WEBP, PNG, etc.) to stdout for scripting.
--preview Flag Streams raw binary preview image bytes directly to stdout (for saving or piping).
-v, --verify Flag Explicitly runs and prints cryptographic Ed25519 signature audit, Merkle commitments, and RS parity status.
--json Flag Outputs token metadata, attestation status, and Merkle root as pure JSON.
Piping Preview: You can pipe binary preview images directly to disk or viewers using tinytoken tok.token --preview > preview.webp.

Usage Examples

Inspect token metadata and fields 
# Display detailed breakdown of all 3 token sections
tinytoken tok_00004_Henri.jpg.token --info
Verify cryptographic signature & Merkle root 
# Run tamper-detection audit
tinytoken tok_00004_Henri.jpg.token -v
Create a token from an image 
# Pack single asset into a 25 KB token
bun tokenize ./images/Henri.jpg -o ./output/henri.token --info

generate

Batch token generator and archive indexing engine

Win11TokenPipeline

Scans entire directories of images and documents concurrently using a 4-worker pool. Generates 384x384 WebP previews, downsamples to 16x16 VQ grids, computes real Meta DINOv3 ViT-S/16 384-byte vectors, and packs the results into tokens.zip.

tinytoken generate [source_dir] [options]

Arguments & Options

Parameter Type Description
[source_dir] Directory Directory of source images to ingest. Defaults to ./images.
-d, --doc-dir <path> Directory Directory containing PDF, DOCX, or text files. Defaults to ./documents.
-o, --output <path> Path Output archive path. Defaults to ./data/tokens.zip.
--workers <count> Integer Parallel concurrency workers. Defaults to 4.
--no-zip Flag Emits standalone *.token files on disk instead of writing a ZIP archive.
Deterministic Ordering: Workers run concurrently, but output tokens are sorted deterministically so archive CRC-32 hashes remain strictly reproducible across identical input trees.
Batch generate archive 
# Build standard tokens.zip from ./images and ./documents
tinytoken generate ./images -d ./documents -o ./data/tokens.zip

search

Multi-modal visual, semantic, and OCR search engine

SearchEngine

Executes sub-5ms queries over the in-memory token index. Combines Level 1/2 VQ Centroid Histogram Intersection (ADC distance) with Level 3 DINOv3 ViT-S/16 cosine similarity, plus full Unicode OCR substring matching.

tinytoken search <query> [options]

Arguments & Options

Parameter Type Description
<query> REQUIRED String OCR text query, token ID, or abstract recipe label to match against.
-m, --mode <type> Enum Search modality: hybrid (default), semantic, color, or ocr.
-k, --top-k <count> Integer Maximum candidate results returned. Defaults to 10.
--image <path> Path Query by visual example using a reference image or existing token.
Fused Metric: Hybrid search scores candidate tokens using Score = α · DINO_sim + (1 - α) · VQ_overlap, where α = 0.60 balances semantic invariance with material color fidelity.
Search tokens by text 
# Hybrid search for charred bark with top 5 hits
tinytoken search "charred tree bark" -m hybrid -k 5

struct

Zero-copy binary field extractor & fast slice iterator

Zero-Copy Mmap

Inspects specific fields directly from raw binary slices without decoding or decompressing the entire token. Enables ultra-fast looping through millions of tokens at memory-bus speeds (>1.2 GB/s).

tinytoken struct <file|archive> [options]

Arguments & Options

Parameter Type Description
<file|archive> REQUIRED Path Single .token file or tokens.zip archive.
-f, --field <name> Enum Target field: uuid, merkle, vq, flags, dims, or all.
--format <fmt> Enum Output format: table, csv, json, or raw-hex.
--filter <expr> Filter Filter expression (e.g. flags.hasDino==true or width>500).
Zero Allocation: Section I fields are extracted via typed DataView offsets without allocating new heap buffers.
Extract fields in table format 
# Extract UUID and Merkle roots across archive
tinytoken struct ./data/tokens.zip --field uuid,merkle --format table

stream

Real-time binary streaming pipe and live edge feed

Binary IPC Pipe

Streams raw binary tokens or uncompressed preview frames continuously over standard output, FIFO sockets, or chunked HTTP responses for live client image renderers and distributed edge nodes.

tinytoken stream <archive> [options]

Arguments & Options

Parameter Type Description
<archive> REQUIRED Path Path to source tokens.zip archive to stream.
-p, --port <port> Integer Serve WebSocket or chunked HTTP stream on specified port.
--fps <rate> Float Stream rate throttle in tokens/sec. Defaults to unthrottled.
--preview-only Flag Streams only the WebP preview image slices instead of the complete 25 KB envelopes.
Raw Terminal Stream: Streaming binary tokens directly to a terminal output will emit raw bytes. Always redirect to a file or pipe into an image consumer.
Stream tokens to pipe 
# Stream previews at 30 fps to external viewer
tinytoken stream ./data/tokens.zip --preview-only --fps 30 | ffplay -
